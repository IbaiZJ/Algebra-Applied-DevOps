# Lab 1: SCRUM & Requirement analysis
Analyze the project scenario to identify key stakeholders, functional features, and non-functional constraints.
These tasks can help you structure the required `README.md` document of the project's Github repository. Besides performing requirement analysis and categorization, you should also define  SCRUM artifacts (product backlog and sprint backlog) and schedule SCRUM ceremonies (planning, review, retrpospective) as well as define what would trigger refeinment of the product backlog.

This is a simple start, and this document will be used for the following sessions (task decomposition) and as a basis for Github Project definition as well as its corresponding issues and complete workflow.

**To start download and read the project task from Moodle**.

---

### Task 1
Create a public GitHub repository for the project and initialize a `README.md` file to document the functional/non-functional requirements analysis.

### Task 2
Identify distinct user roles specified in the project scenario and describe them. Map out the allowed actions for each role to support Role-Based Access Control (RBAC).

### Task 3.1
Translate requirements into standardized User Stories and establish a prioritized Product Backlog. In the next session you will categorize each functionality under arbitrary epic and deconstruct the user story into tasks. 

Formulate stories using the standard template (*As a [Role], I want [Feature], so that [Benefit]*), e.g.:
- *US-01*: As a [STUDENT], I want to [register for an exam], so that [I can attend the exam and score the final grade].
- ...

Make up additional User Story for each role.

### Task 3.2
Assume the role of **Product Owner** to organize all user stories into a sorted **Product Backlog** based on implementation priority.

### Task 4
Plan activities for the lifetime of the project development:
- Duration of the sprint 
- Sprint Planning
- Sprint Review
- Sprint Retrospective
