Requirement IDs link each story to the functional and non-functional requirements in [02-Requirements-analysis.md](02-Requirements-analysis.md). ### Prioritisation rationale

1. **US-01 is first** because staff must authenticate and receive role-appropriate access before any protected workflow can be used.
2. **US-02 and US-03 follow** because doctor and patient records are prerequisites for scheduling and for a meaningful end-to-end demonstration.
3. **US-04 is next** because it connects the core records and addresses the high-risk double-booking constraint early.

The three additional stories are explicitly marked. They extend the required scope only after the core hospital workflows are available.

### Definition of Done

A backlog item is done only when:

- Its acceptance criteria pass and the linked FR/NFR requirements are met.
- Relevant unit and API integration tests pass; affected end-to-end workflows are covered by Playwright tests.
- Role permissions, input validation, error handling and privacy expectations are checked for the changed workflow. Applicable cross-cutting NFRs are verified, including HTTPS and secure configuration, protections against common web threats, performance, accessibility and recovery behavior.
- Database migrations, if any, are documented and run successfully in the project environment.
- The change is reviewed and merged through a pull request after all required CI checks pass; no work is pushed directly to `main`.
- The application container builds successfully, and the image is published to GHCR from the main-branch delivery pipeline.
- User and operator documentation is updated when behavior, setup or operational procedures change.
